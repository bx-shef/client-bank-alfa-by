# С чего начать в этом коде

> Last reviewed: 2026-07-30

Маршрут для того, кто видит проект впервые. [`CLAUDE.md`](../CLAUDE.md) — справочник (его читают
выборочно, по оглавлению), а здесь — порядок, в котором код становится понятным.

## Главный сценарий: файл выписки → дело в CRM

Читать подряд, держа рядом `app/types/statement.ts` (модель операции — к ней всё сводится):

1. **[`PROCESSING.md`](PROCESSING.md) §0 «Путь данных»** — карта на одну страницу. До кода.
2. **`app/utils/importUpload.ts`** — вход: проверка файла, декод windows-1251, `decodeAndParse`.
3. **`app/utils/manualImport.ts` → `clientBankStatement.ts`** — определение формата и нормализация
   в `StatementItem[]`. Здесь видно, почему форматов несколько и чем они отличаются.
4. **`server/api/import.post.ts` + `server/utils/importIngest.ts`** — граница доверия: фрейм-токен,
   гейт файла, постановка в очередь. Сервер — единственный авторитет разбора; браузерный разбор на
   `/import` это только предпросмотр.
5. **`server/queue/topology.ts`** — очереди и payload'ы, затем **`server/queue/handlers.ts`,
   функция `handleCrmSyncJob`** — сердце системы: дедуп → компания → распознавание → разнесение →
   запись дела → чат. Самый важный файл проекта.
6. **`server/utils/companyLookup.ts`** — как расчётный счёт превращается в компанию CRM (два
   REST-шага) и что делает фолбэк «моя компания», когда плательщик не опознан.
7. **`app/utils/purposeMatch.ts` + `app/utils/allocation.ts`** — распознавание номера в назначении и
   решение о разнесении. Обе чистые и под тестами — лучшая точка для первой правки.
8. *(по желанию)* **`server/queue/worker.ts`** — где чистые ядра сшиваются с живыми транспортами.

Онлайн-путь (банк вместо файла) отличается только началом: `server/queue/cron.ts` планирует опрос →
очередь `bank-fetch` → нормализация → тот же `crm-sync`.

## Что можно потрогать без портала Bitrix24

Портал нужен для записи в CRM, настроек и онлайн-опроса. Всё остальное доступно сразу:

```bash
pnpm test --project unit                       # вся доменная логика, секунды
pnpm parse:statement public/samples/<файл>.txt # разбор реального файла в консоль
pnpm fuzz:allocation 42 500                    # прогон алгоритма разнесения на синтетике
pnpm dev                                       # / — демо «попробуйте на своей выписке»
```

Страницы приложения вне портала закрыты заглушкой — открывайте с `?preview=1`
(`/app?preview=1`, `/import?preview=1`) **в браузере**: гейт резолвится на клиенте, поэтому `curl`
покажет пустую страницу и создаст ложное впечатление, что не работает.

Примеры выписок лежат в `public/samples/` (их же отдаёт демо на лендинге) и в `tests/fixtures/` —
последние покрывают форматы, на которых проект уже ловил баги.

## Словарь

Термины, которые в остальных документах употребляются как известные.

- **Операция** (`StatementItem`) — одна строка выписки после нормализации: счёт, сумма, валюта,
  направление, контрагент, назначение. Единый вид для всех банков и форматов.
- **Интент** — распознанное в назначении намерение «платёж относится к сущности X»: пара «вид
  идентификатора + значение» (`invoice-number: СЧ-1024`).
- **Матрица распознавания** — шаблон номера: маска (`d` — цифра, `d+` — одна или больше) плюс
  литералы и вид сущности (`СЧ-d+`). Настраивается админом портала, в коде номеров нет.
- **Разнесение (аллокация)** — привязка пришедших денег к конкретной цели в CRM (смарт-счёт, оплата
  сделки, сделка, элемент смарт-процесса) и, при включённом авто-проведении, пометка её оплаченной.
- **dist-СП** — служебный смарт-процесс **в самом портале клиента**, где лежит леджер разнесений
  («платёж → цель → сумма»). Намеренно там, а не в нашей БД: данные принадлежат клиенту.
- **Фрейм-токен** — временный токен, который портал выдаёт странице внутри iframe. Наши API им
  доказывают, что запрос действительно из этого портала. Это настоящая граница авторизации —
  в отличие от `?preview=1`, который лишь UX-заглушка.
- **Маркер дедупа** — пара `originatorId`+`originId` на настраиваемом деле в B24. Перед записью
  операции мы ищем по ней; своей таблицы дедупа нет, источник истины — сам портал.
- **«Моя компания»** — наша собственная организация в CRM (`isMyCompany=Y`). Туда уходит дело,
  когда плательщика опознать не удалось, чтобы платёж не потерялся.
- **`app.option`** — хранилище настроек на стороне портала; наши настройки живут там, а не у нас.
